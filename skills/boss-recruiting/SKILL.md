# Boss 直聘招聘初筛（技能入口）

> 本文解决什么问题：给 Agent 一份**可执行的作业规程**——何时用、用什么工具、按什么口径、守什么底线、交什么产物。

---

## 用之前先确认三件事

### ① 工具是否可用

```bash
# 优先：MCP 工具（若已挂载 dsh-plugin）
#   mcp__boss__doctor / mcp__boss__list / mcp__boss__capture_resume / ...

# 退路：命令行
boss --version
boss doctor
```

桥的状态：

```bash
curl -s http://127.0.0.1:8898/status
# 必须看到 "extensionConnected": true
```

**不满足就不要往下走**——继续操作只会得到一堆超时。先看 [TROUBLESHOOTING.md](../../docs/TROUBLESHOOTING.md#1-extensionconnected-false)。

### ② 浏览器是否合规

| 必须 | 必须不是 |
| --- | --- |
| **可见窗口** | ❌ 无头模式 `--headless` |
| **已登录招聘账号** | ❌ 未登录 / 登录态过期 |
| **带扩展加载**（`--load-extension`） | ❌ 带 `--remote-debugging-port`（会被站点检测并关页） |
| **专用 profile** | ❌ 主力日常 profile |
| **境内直连** | ❌ 境外代理 |

```bash
boss doctor   # 期望全 [✓]
```

### ③ 是否读了坑清单

**开工前必读** [docs/PITFALLS.md](../../docs/PITFALLS.md)。里面每一条都会在实操中**再次遇到**：非前台不渲染、大响应卡死、弹层叠层、同名发错人……

## 六条铁律

> **违反任何一条，结果就不可信。**

### 铁律 1 · 一切按会话 id + 指纹核对（防重名）

- **姓名只用于搜索**，所有操作一律用**会话 id**；
- 打开后**必须**核对指纹，**全部一致**才继续：
  ```
  姓名 + 年龄 + 学历 + 工作年限 + 当前公司及岗位
  ```
- 任何一项不符 → **立即中止**，记录 `FINGERPRINT_MISMATCH`；
- 结果里记录**实际打开到的人是谁**，保证可审计。

```bash
boss open <candidate-id>
```

**例外识别**：同一个人可能有多条会话（不同职位/重复打招呼），表现为「同名 + 同年龄 + 同学历 + 同年限，公司名差一两个字」→ 属**同一人**，不是发错。

### 铁律 2 · 每个维度都要有原文证据

- **每个评分维度都必须附候选人原文摘录**；
- **没有摘录的维度按 0 分**——这是硬规则；
- 摘录**逐字**来自简历或打招呼留言，**不允许改写**；
- 摘录要能定位（第几屏 / 哪一段）。

### 铁律 3 · 写操作必须可核验

| 操作 | 核验标准 |
| --- | --- |
| 发消息 | **输入框已清空** ✅ **且** **会话里出现该消息** ✅ |
| 求简历 | 会话里出现系统消息「**简历请求已发送**」 |
| 收藏 | 先读当前状态再点（避免把「已收藏」点成「取消」） |
| 下载简历 | 文件头为 `%PDF` |

**不接受**「函数返回成功」「按钮已点击」这类弱确认。

```bash
boss send <candidate-id> --text "<开场话术>"
```

### 铁律 4 · 幂等

- **重复运行不得重复发送**；
- 执行前先查状态（已发过就跳过、已收藏就不点、已下载就不重下）；
- 卡住/超时后**不要盲目重发**——先 `boss open <candidate-id> --messages 20` 确认到底发出去没有。

### 铁律 5 · 节奏控制

| 参数 | 默认 |
| --- | --- |
| 单人间隔 | **15–20 秒** |
| 连续工作 | **40–60 分钟**后冷却 |
| 冷却时长 | **30–60 分钟** |
| 首轮规模 | **（建议 3–5 人先验证链路）** |

**看到简历画布停在 300×150 且手动也渲染不出 → 立即停手冷却**，不要重试（重试会延长冷却）。

### 铁律 6 · 交付目录只放交付物

- 交付目录**只放四项交付物**；
- 过程产物（列表 JSON、分块截图、会话快照、日志、中间评分表）全部移到 `_过程文件/`；
- 交付前跑 `boss audit --people <名单>.json --json` 逐人核验。

## 两段式 SOP 摘要

### 第一段 · 列表级硬门槛（**不开简历**）

**字段**：年龄 / 学历 / 工作年限 / 当前公司及岗位 / 期望城市薪资 / **打招呼留言全文（多轮都要）**

| 门槛 | 规则 |
| --- | --- |
| G1 学历 | 本科及以上；**大专扣 5 分可入池**；大专以下淘汰 |
| G2 年限 | ≥ 1 年正式经验（实习不计） |
| G3 地域 | 大湾区，**深圳优先** |
| G4 薪资 | 期望上限 **≤ 16K**（留言里说可谈的进人工复核） |
| G5 方向 | 开发岗，与在招方向一致 |
| G6 到岗 | 可到岗（明确「暂不考虑」则淘汰） |

**产出**：`通过 / 淘汰 + 淘汰原因（要能复述）+ 原文证据`

```bash
boss list --limit 200 --json > ./_过程文件/list.json
# G1–G6 判定由你/Agent 按上表执行 → 写 ./_过程文件/stage1.json
```

### 第二段 · 在线简历精筛（**八维度 100 分**）

| 维度 | 名称 | 满分 |
| --- | --- | --- |
| D1 | 独立闭环交付 | **25** |
| D2 | 业务理解与需求拆解 | **20** |
| D3 | 技术栈重合度 | **15** |
| D4 | 稳定性与性价比 | **15** |
| D5 | 工程化交付 | **12** |
| D6 | 接手维护旧系统 | **5** |
| D7 | ERP / 低代码 / 二开 | **4** |
| D8 | AI 辅助编码实操 | **4** |

**否定项**

| 否定项 | 扣分 |
| --- | --- |
| 纯算法，无业务系统 | **−15** |
| 仅大厂细分模块 | **−10** |
| 近两段经历每段 < 1 年 | **−15** |
| 履历矛盾 | **−20** |
| 大专 | **−5** |

**阈值**

```
S ≥ 70   优先约面
A 55–69  推荐
B 40–54  观望
C 25–39  暂不推进
D < 25   淘汰
```

> ⚠️ **AI / RAG / Agent 本身不作为加分项。**
> 只有 **D8** 认可「用 AI 工具提升编码效率」的**实操痕迹**；方向性能力只看 **D1/D2 的业务系统交付**。
> 理由：AI 名词极易包装且无法在初筛阶段证伪。

```bash
boss capture-resume <candidate-id> --out ./_过程文件/resume/<candidate-id> --screens 12 --scale 0.9
# 八维度打分由你/Agent 读图后写入 ./_过程文件/scores.json（每维必须带原文摘录）
```

### 触达与收集

```
1. 开场话术 → 一句话认可 + 只提「方便发一份 PDF 简历吗」
              （异地/超预算才顺嘴说明；不要问到岗时间）
2. 求简历   → 两步确认，以系统消息「简历请求已发送」核验
3. 收藏     → 先读状态再点
4. 收简历   → 附件简历 → 预览 iframe 的 url 参数解出真实地址 → 下载 → 校验 %PDF
5. 致谢     → 收到后回一条标准致谢
```

## 交付物契约

**每次固定产出以下四项，不多不少。**

```
输出/
├── 最终筛选名单_<岗位>.xlsx        ← 名单 + 维度得分 + 评分口径 + 跟踪列
├── 人才画像与筛选标准_<岗位>.docx   ← 唯一一份文字材料
├── 在线简历汇编报告.pdf             ← 每人 1 页评分摘要 + 在线简历逐屏截图
└── 简历PDF/                        ← 收到的附件简历（<序号>_<姓名>.pdf）
```

| 交付物 | 关键要求 |
| --- | --- |
| 名单 xlsx | **必含会话 id 列**；D1–D8 各一列；否定项列；总分/分级列；评分口径列；`已发送/已收藏/已收简历/已回复` 四个跟踪列 |
| 人才画像 docx | 四部分：人才画像、硬门槛、评分规则、**面试验证清单**（初筛无法证伪的点） |
| 在线简历报告 pdf | **每人 1 页**，评分摘要 + 逐屏截图，顺序与名单一致 |
| 简历PDF 目录 | `<序号>_<姓名>.pdf`，与名单序号一一对应；**重名时加会话 id 后 6 位，不要覆盖** |

> 过程产物放 `_过程文件/`，**不进交付目录**。

```bash
# 四项交付物由你/Agent 按下面契约生成到 输出/（xlsx / docx / pdf / 简历PDF）
# 核验：逐人查指纹 + 话术 + 求简历 + 收藏
boss audit --people ./_过程文件/people.json --json
```

## 常见错误自查

| 自查项 | 错在哪 | 后果 |
| --- | --- | --- |
| 用姓名直接点列表行 | 没用会话 id | **可能发给重名的另一个人**（最高危，不可撤回） |
| 打开后立刻读快照 | 没用轮询等指纹 | 读到上一个人的数据，**评分全错** |
| 以为简历没加载 | 没检查窗口是否在前台 | 对着 300×150 空图评分 |
| 抓图返回为空/超时 | 没分块（单块 > 约 55KB 就卡） | 调用卡死 |
| 看到窄栏文字浮层 | 没清叠层 | 误判为页面异常，抓错内容 |
| 发送/求简历「成功」但无记录 | 用返回值而非会话消息核验 | 以为发了其实没发 |
| 卡住后反复重发 | 违反幂等 | **重复发送**给候选人 |
| 某个维度没摘录却给了分 | 违反铁律 2 | 报告不可信，HR 无法复核 |
| AI/RAG 经历加分 | 违反评分规则 | 排序被名词热度带偏 |
| 过程文件混进交付目录 | 违反铁律 6 | HR 拿到不知道看哪个 |
| 500 人一次性跑完 | 违反节奏控制 | 触发限流，画布停渲染，当天报废 |

## 一句话流程

```
doctor 自检
  → list 拉列表（记全文留言）
  → screen --stage list（G1–G6 硬门槛）
  → 逐人：open（按 id + 指纹核对）→ capture-resume（分块）
          → screen --stage resume（八维度 + 原文证据）
          → send 开场 → request-resume → favorite
          → download-resume（收附件，校验 %PDF）→ send 致谢
  → report（名单 / 画像 / 汇编）
  → audit（一致性检查）
  → 交付
```
